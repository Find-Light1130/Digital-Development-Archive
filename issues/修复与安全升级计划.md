## 一、现状与根因分析

### 1.1 逐项问题根因

| # | 问题 | 根因 |
|---|------|------|
| 1 | 下拉框高亮与主题不符 | `App.vue` 中 `.el-select-dropdown__item.is-hovering` 硬编码 `rgba(36,14,64,0.6)`，与深色主题期望色（`#240E40`/`#241E41`）不一致，且未变量化 |
| 2 | 教师端"各科平均掌握率"X 轴文字倾斜/拥挤 | 9 个科目挤在同一横轴，长科目名（道德与法治）未换行、底部空间不足 |
| 3 | 学生成绩出现"空缺"（如 ID=214 "4月月考"） | **考试标签冲突**：`EXAM_WEEKS=[2,6,10,14,18]` 在 2 月中旬开学的学期里第 2、6 周均落在 3 月，产生两个 `3月月考`；跨学期 `期中/期末` 标签重复。前端按 label 去重，把真实考试静默隐藏。数据本身完整（全校 147000 条成绩、0 条 NULL），且当前数据根本没有"4月月考" |
| 4 | 学生折线图数据点难以点击 | 数据点小（12px）、仅点中符号才触发、无十字辅助线、点击容差低 |
| 5 | 教师端趋势图 tooltip 缺每次考试的最高/最低/平均 | 同根因 3：`期中/期末/3月月考` 被去重，约 3/5 的考试点缺失，无法悬浮查看 |
| 6 | 教师端返回后班级丢失 | 通过下拉选择班级时 URL 未同步 `?class=`，返回重挂载后 `route.query.class` 为空；`sessionStorage` 兜底缺失 |
| 7 | "持续下滑"描述不准确 | `_trend()` 只比较"前 2 次 vs 后 2 次"的均值（看部分），且"持续下滑"只查最近学期；应改为"整学期所有考试单调递减" + 全局线性趋势 |

### 1.2 排查出的其他问题

- **安全（非登录类）**：CORS `allow_origins=["*"]`；后端绑定 `0.0.0.0`；POST 接口 `date` 未严格校验、未校验 student_id 是否存在（FK 报 500）；缺少 CSP/Referrer-Policy 等响应头。
- **正确性**：`admin_api.py` 缓存 TTL 混用 `time.time()` 与 `time.monotonic()`，导致缓存首次过期后**永不刷新**；`_recent_mastery` 依赖插入序而非日期序。
- **体验**：ScoreChart/Teacher 对照表列序错误（`期中` 排到更早的月考之前）；ECharts tooltip 深色硬编码，浅色模式下不协调且切主题不刷新。

## 二、核心决策

### 决策 1：考试时间安排 —— 调整考试周 + 重建数据 ✅

将 `data/raw_data_gen.py` 的 `EXAM_WEEKS` 由 `[2,6,10,14,18]` 改为 `[4,8,10,14,18]`：

- 9 月开学学期：月考落在 9/10/12 月，期中 11 月、期末 1 月 → 各月考月份唯一；
- 2 月开学学期：月考落在 3/4/5 月（**产生真正的"4月月考"**，如 `2026-04-13`），期中 4 月底、期末 6 月 → 各月考月份唯一。

副作用：全校所有考试日期后移约 2 周；重建 `data/school.db`。

### 决策 2：会话/登录系统 —— 暂缓 ⏸️（后续探讨）

按用户指示，用户登录/角色权限系统本次**不实施**，后续再出详细方案（含：本地 vs 云端会话存储的权衡、JWT vs 服务端 Session、角色模型等）。本计划不包含认证改造。

## 三、详细实施计划

### 3.1 数据层

1. **`data/raw_data_gen.py`**
   - `EXAM_WEEKS` 改为 `[4, 8, 10, 14, 18]`。
   - 重建数据库 + 重新导出 CSV。

### 3.2 问题 1 ～ 7 修复

2. **问题 1 · 下拉框主题化**（`frontend/src/App.vue`）
   - 新增变量：`--dropdown-item-hover-bg`（深色 `linear-gradient(135deg,#240E40,#241E41)`；浅色保持 `rgba(0,0,0,.04)`）、`--dropdown-focus-border`（深色 `#241E41`；浅色 `rgba(0,0,0,0.15)`）。
   - 应用到 `.el-select-dropdown__item.is-hovering` 与 `.el-select__wrapper.is-focused/.is-hovering`。

3. **问题 2 · 掌握率条形图横排文字**（`frontend/src/views/TeacherDashboard.vue` `masteryOption`）
   - `axisLabel: { interval:0, rotate:0, fontSize:11, lineHeight:15, align:'center' }` + formatter 对 >2 字科目折行（如 `道德与\n法治`）；`grid.bottom≈96`；`axisTick.alignWithLabel`。

4. **问题 3/5 · 考试标签唯一化**（数据 + 显示双层修复）
   - `backend/routes/teacher_api.py`：每个趋势条目新增 `date` 字段；输出前对整班数据做标签唯一化——基名重复（`期中`/`期末`/`X月月考`）时追加 `·M-D`（如 `期中·04-27`）。
   - `frontend/src/components/ScoreChart.vue`：`examLabel` 改为"按日期排序 + 冲突追加 `·M-D`"的唯一标签；**表格列按考试实际日期升序**（修复"期中"排在月考之前）；去掉按 label 去重的逻辑。
   - `frontend/src/views/TeacherDashboard.vue`：`teacherTrendData`/`teacherColumns` 基于唯一标签且不去重；对照表列按 `date` 排序。

5. **问题 4 · 折线图点击优化**（`frontend/src/components/ScoreChart.vue`）
   - `symbolSize:14`、`emphasis.scale≈2.2`（加阴影）；`tooltip.triggerOn:'mousemove|click'` + `axisPointer:{type:'line'}`。
   - 点击逻辑：命中 series 数据点照旧；另通过 `chart.getZr()` 捕获近邻（≤30px）点；支持点击 X 轴刻度映射到最近考试；底部提示改为"点击数据点或附近区域查看考试详细总结"。

6. **问题 5 · 趋势 tooltip 最高/最低/平均**（`frontend/src/views/TeacherDashboard.vue` `teacherTrendOption`）
   - 每个考试点 tooltip 展示：科目+考试名、**平均分**、**最高分**、**最低分**、得分率。
   - 趋势图 `axisLabel.interval:'auto'`，保证 10–30 个点全部可悬浮但标签不拥挤。

7. **问题 6 · 班级选择持久化**（`frontend/src/views/TeacherDashboard.vue` / `frontend/src/views/StudentDetail.vue`）
   - 班级变化时 `router.replace({ query:{ class } })` 同步 URL；`sessionStorage` 存最近班级。
   - 挂载时优先 `route.query.class`，其次 `sessionStorage`；`StudentDetail.goBack` 保留 `?class=` 参数并做 `router.back()` 兜底。

8. **问题 7 · 下滑描述修正**（`backend/ai_modules/analysis.py`）
   - 新增 `_overall_trend(pcts)`：对全部成绩做线性回归斜率；阈值 `< -1.0/次` 判"下滑"、`> +1.0/次` 判"上升"、否则"平稳"（替代旧的"前 2 次 vs 后 2 次"）。
   - 预警/建议规则：
     - 存在**整学期所有考试单调不减**（沿用 `_is_monotonic_decreasing`）→ 措辞 `{科目}本学期成绩持续下滑，需关注`；
     - 否则若整体斜率下降 → `{科目}成绩整体呈下滑趋势`（"有下滑"）；
     - 建议模板区分"持续下滑（错题本/系统复习）"与"下降趋势（调整方法）"两档。

### 3.3 其他修复（非登录类安全加固）

9. **`backend/routes/admin_api.py`**：`_get_indices`/`_warm_cache`/`_get_or_compute` 统一使用 `time.monotonic()`，修复缓存永不过期。
10. **`backend/app.py`**：CORS 限定来源（去掉 `*`）；`__main__` 绑定 `127.0.0.1`；新增 `Content-Security-Policy`、`Referrer-Policy`、`Permissions-Policy` 响应头（保留现有 nosniff/iframe/缓存头）。
    - CSP 采用演示可用策略：`default-src 'self'; script-src 'self' 'unsafe-inline'; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob:; connect-src 'self' ws: http: https:; font-src 'self' data:`。
11. **`backend/routes/student_api.py` / `teacher_api.py`**：`submit_emotion` / `add_student_event` 的 `date` 用 `datetime.strptime(..., "%Y-%m-%d")` 严格校验；校验 student_id 存在（不存在返回 404）；保留原有范围校验。
12. **`backend/ai_modules/analysis.py`**：`_recent_mastery` 先按 `date` 排序再取最近 3 次。
13. **图表主题化**：`frontend/src/utils/colors.js` 新增 `themeTooltip()` / `themePalette()`；ScoreChart / TeacherDashboard / AdminDashboard 的 ECharts tooltip 背景/文字读取 CSS 变量，并 `void themeKey.value` 使切主题即时刷新。

### 3.4 验证方案

- 重建数据：`python data/raw_data_gen.py`，检查输出统计与 `test/verify.py`、`test/perf_check.py`。
- 后端：`uvicorn backend.app:app --port 8000`，抽查学生 214 成绩完整性、班级趋势唯一标签、POST 日期校验。
- 前端：`cd frontend && npm run build`（编译检查）+ `npm run dev` 手动回归：下拉主题、掌握率横排、折线图点击、趋势 tooltip、班级返回持久化、学生 214 与某初三班级显示全部唯一标签考试点。

## 四、风险与注意事项

- **数据重建副作用**：所有考试日期整体平移约 2 周；CSV 与演示数据随之变化。
- **CSP 策略**需在 Vite 开发与 `npm run build` 产物下分别验证，若 HMR/样式受影响会放宽 `style-src`。
- 登录系统（含角色权限、会话存储方案）另行立项，本次不实现。
